
## Overview

The `type()` function in Python is used to:

1. Determine the data type of an object at runtime.
    
2. Dynamically create classes.
    

It is commonly used for debugging, type checking, and understanding how Python objects are represented internally.

---

# Syntax

## 1. Get the Type of an Object

```python
type(object)
```

### Parameters

- `object` → The value or variable whose type you want to determine.
    

---

## 2. Create a Class Dynamically

```python
type(name, bases, dict)
```

### Parameters

|Parameter|Description|
|---|---|
|`name`|Name of the class to create|
|`bases`|Tuple of base classes|
|`dict`|Dictionary containing attributes and methods|

---

# Basic Example

```python
x = 10
print(type(x))
```

### Output

```text
<class 'int'>
```

### Explanation

- `x` stores the integer value `10`.
    
- `type(x)` returns the type of the object.
    
- Since `10` is an integer, Python returns `int`.
    

---

# Example 1: Checking Different Data Types

```python
a = 5
b = "Hi"
c = [1, 2]

print(type(a))
print(type(b))
print(type(c))
```

### Output

```text
<class 'int'>
<class 'str'>
<class 'list'>
```

### Explanation

|Variable|Value|Type|
|---|---|---|
|`a`|`5`|`int`|
|`b`|`"Hi"`|`str`|
|`c`|`[1, 2]`|`list`|

---

# Example 2: Comparing Types

```python
x = 10
y = 5.5

print(type(x) is type(y))
```

### Output

```text
False
```

### Explanation

- `x` is an integer (`int`)
    
- `y` is a floating-point number (`float`)
    
- `type(x)` and `type(y)` are different objects
    
- Therefore the result is `False`
    

> [!note]  
> The `is` operator checks whether two objects are the same object in memory.

---

# Example 3: Creating a Class Dynamically

```python
A = type("A", (), {"x": 100})

obj = A()

print(type(obj))
print(obj.x)
```

### Output

```text
<class '__main__.A'>
100
```

### Explanation

```python
type("A", (), {"x": 100})
```

Creates a class equivalent to:

```python
class A:
    x = 100
```

Then:

```python
obj = A()
```

creates an object of class `A`.

---

# Example 4: Checking if Two Objects Have the Same Type

```python
a = [1, 2]
b = (1, 2)

print(type(a) == type(b))
```

### Output

```text
False
```

### Explanation

- `a` is a list
    
- `b` is a tuple
    
- Lists and tuples are different data types
    

Therefore:

```python
type(a) == type(b)
```

evaluates to `False`.

---

# Example 5: Dynamic Class with Attributes and Methods

```python
B = type(
    "B",
    (),
    {
        "n": 5,
        "show": lambda self: self.n
    }
)

o = B()

print(type(o))
print(o.show())
```

### Output

```text
<class '__main__.B'>
5
```

### Explanation

The following class is created dynamically:

```python
class B:
    n = 5

    def show(self):
        return self.n
```

Then:

```python
o = B()
```

creates an object and:

```python
o.show()
```

returns the value of `n`.

# `type()` vs `isinstance()`

Although `type()` is useful, `isinstance()` is often preferred for type checking.

## Using `type()`

```python
x = True

print(type(x) == int)
```

### Output

```text
False
```

---

## Using `isinstance()`

```python
x = True

print(isinstance(x, int))
```

### Output

```text
True
```

### Why?

In Python:

```python
bool
```

is a subclass of

```python
int
```

`isinstance()` considers inheritance, while `type()` checks only the exact type.

> [!tip]  
> Use `isinstance()` when checking types in real-world programs.

---

# Common Use Cases

## Debugging

```python
data = [1, 2, 3]

print(type(data))
```

---

## Validating User Input

```python
value = 10

if type(value) == int:
    print("Integer received")
```

---

## Dynamic Programming

```python
MyClass = type(
    "MyClass",
    (),
    {"name": "Python"}
)

obj = MyClass()
print(obj.name)
```

---

# Summary

- `type()` returns the type of an object.
    
- It can also dynamically create classes.
    
- Useful for debugging and inspecting objects.
    
- `type(obj)` returns the exact type.
    
- `type(name, bases, dict)` creates a class dynamically.
    
- For type checking, `isinstance()` is usually preferred because it supports inheritance.
