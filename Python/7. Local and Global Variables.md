
## Overview

Variables store data in memory, while **scope** determines where a variable can be accessed within a program.

Python variables are primarily categorized into:

1. **Local Variables**
    
2. **Global Variables**
    

Understanding variable scope is important for writing clean, maintainable, and bug-free code.

---

# Local Variables

A **local variable** is defined inside a function and exists only while that function is executing.

- Accessible only within the function where it is created.
    
- Destroyed when the function finishes execution.
    

## Example 1: Accessing a Local Variable

```python
def greet():
    msg = "Hello from inside the function!"
    print(msg)

greet()
```

### Output

```text
Hello from inside the function!
```

### Explanation

- `msg` is created inside `greet()`.
    
- It exists only while the function runs.
    
- Accessing it inside the function works correctly.
    

---

## Example 2: Accessing a Local Variable Outside Its Function

```python
def greet():
    msg = "Hello!"
    print("Inside function:", msg)

greet()
print("Outside function:", msg)
```

### Output

```text
Traceback (most recent call last):
NameError: name 'msg' is not defined
```

### Explanation

- `msg` exists only inside `greet()`.
    
- Once the function finishes, `msg` is no longer available.
    
- Attempting to access it outside the function raises a `NameError`.
    

> [!warning]  
> Local variables cannot be accessed outside the function where they are defined.

---

# Global Variables

A **global variable** is declared outside all functions.

- Accessible throughout the program.
    
- Can be read inside functions.
    
- Exists until the program terminates or the variable is deleted.
    

## Example

```python
msg = "Python is awesome!"

def display():
    print("Inside function:", msg)

display()
print("Outside function:", msg)
```

### Output

```text
Inside function: Python is awesome!
Outside function: Python is awesome!
```

### Explanation

- `msg` is declared globally.
    
- It can be accessed both inside and outside the function.
    

> [!note]  
> If Python cannot find a variable in the local scope, it automatically searches the global scope.

---

# Local Variables Shadow Global Variables

When a local variable and a global variable share the same name, the local variable takes precedence inside the function.

## Example

```python
def fun():
    s = "Me too."
    print(s)

s = "I love GeeksforGeeks"

fun()
print(s)
```

### Output

```text
Me too.
I love GeeksforGeeks
```

### Explanation

- The local variable `s` exists only inside `fun()`.
    
- The global variable `s` remains unchanged.
    
- The local variable **shadows** the global variable within the function.
    

> [!tip]  
> A local variable with the same name as a global variable temporarily hides the global variable inside that function.

---

# Modifying Global Variables Inside a Function

By default, Python does not allow a function to modify a global variable directly.

To modify a global variable, use the `global` keyword.

---

## Without `global` (Raises Error)

```python
def fun():
    s += " GFG"
    print(s)

s = "I love GeeksforGeeks"

fun()
```

### Output

```text
UnboundLocalError: local variable 's' referenced before assignment
```

### Explanation

Python assumes `s` is a local variable because it is being modified.

Since no local `s` exists before the modification, Python raises an error.

---

## With `global` (Works Correctly)

```python
s = "Python is great!"

def fun():
    global s

    s += " GFG"
    print(s)

    s = "Look for GeeksforGeeks Python Section"
    print(s)

fun()
print(s)
```

### Output

```text
Python is great! GFG
Look for GeeksforGeeks Python Section
Look for GeeksforGeeks Python Section
```

### Explanation

- `global s` tells Python to use the global variable.
    
- Changes made inside the function affect the global variable.
    
- The modified value remains available after the function finishes.

# Global vs Local Variables with the Same Name

```python
a = 1  # Global variable

def f():
    print("f():", a)

def g():
    a = 2
    print("g():", a)

def h():
    global a
    a = 3
    print("h():", a)

print("global:", a)

f()
print("global:", a)

g()
print("global:", a)

h()
print("global:", a)
```

### Output

```text
global: 1
f(): 1
global: 1
g(): 2
global: 1
h(): 3
global: 3
```

### Explanation

#### Function `f()`

```python
print(a)
```

Uses the global variable.

#### Function `g()`

```python
a = 2
```

Creates a local variable that shadows the global variable.

#### Function `h()`

```python
global a
a = 3
```

Modifies the global variable directly.

# Scope Resolution (LEGB Rule)

Python searches for variables in the following order:

1. **L**ocal Scope
    
2. **E**nclosing Scope
    
3. **G**lobal Scope
    
4. **B**uilt-in Scope
    

Example:

```python
x = "Global"

def outer():
    x = "Enclosing"

    def inner():
        x = "Local"
        print(x)

    inner()

outer()
```

### Output

```text
Local
```

Python finds `x` in the local scope first and stops searching.

# Global vs Local Variables

|Feature|Global Variable|Local Variable|
|---|---|---|
|Definition|Declared outside functions|Declared inside functions|
|Scope|Entire program|Specific function|
|Lifetime|Until program ends or variable is deleted|Until function returns|
|Accessibility|Anywhere in the program|Only within the function|
|Data Sharing|Shared across functions|Not shared|
|Modification|Can be modified using `global` keyword|Modified freely inside its function|
|Storage|Global namespace|Local namespace (stack frame)|
|Side Effects|Can affect multiple parts of the program|Affects only the function|

---

# Best Practices

> [!tip]  
> Prefer local variables whenever possible.

### Why?

- Easier to debug
    
- Fewer side effects
    
- Better code readability
    
- Functions become more reusable
    

### Avoid Excessive Use of Globals

```python
# Less Preferred
count = 0

def increment():
    global count
    count += 1
```

Instead:

```python
def increment(count):
    return count + 1
```

This approach makes functions more predictable and easier to test.

---

# Summary

- **Local variables** exist only inside a function.
    
- **Global variables** exist throughout the program.
    
- Local variables shadow global variables with the same name.
    
- Use the `global` keyword to modify global variables inside functions.
    
- Python follows the **LEGB** scope resolution rule.
    
- Prefer local variables for cleaner and safer code.
