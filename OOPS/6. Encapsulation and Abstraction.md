
####  1. What is Encapsulation?

## Definition

> **Encapsulation is the process of wrapping data (variables) and methods (functions) together into a single unit (class) and restricting direct access to the data.**

In simple words:

- Data is hidden from outside classes.

- Access to data is controlled using methods.    
- This is achieved using **access modifiers** like `private`, `public`, `protected`.



#  2. Why Encapsulation is Used?

Encapsulation is used for the following important reasons:

## 1️ Data Security (Data Hiding)

We don’t allow outside classes to directly change important data.

Example:
- In a banking app, you should not directly change account balance.

## 2️ Controlled Access
We can apply validation before setting values.
Example:
- Age should not be negative.
- Salary should not be zero.
- Marks should be between 0–100.



## 3️ Flexibility and Maintainability

If internal implementation changes, other classes are not affected.


## 4️ Better Code Organization

Encapsulation keeps related data and methods together in one place.


## 5️ Improves Readability

Well-structured classes are easier to understand.

#  4. How Encapsulation is Implemented in Java?

Encapsulation is implemented using:

### Step 1: Declare variables as `private`

### Step 2: Provide `public` getter and setter methods

### Step 3 (Optional): Add validation inside setters



# 5. Detailed Example with Explanation

## Example: Bank Account

class BankAccount {  

```java

class BankAccount {

    // Step 1: Private variables (Data Hiding)
    private String accountHolder;
    private double balance;

    // Constructor
    public BankAccount(String accountHolder, double balance) {
        this.accountHolder = accountHolder;
        if(balance > 0) {
            this.balance = balance;
        }
    }

    // Step 2: Getter method
    public String getAccountHolder() {
        return accountHolder;
    }

    // Getter for balance
    public double getBalance() {
        return balance;
    }

    // Step 3: Setter with validation
    public void deposit(double amount) {
        if(amount > 0) {
            balance += amount;
        } else {
            System.out.println("Deposit amount must be positive.");
        }
    }

    public void withdraw(double amount) {
        if(amount > 0 && amount <= balance) {
            balance -= amount;
        } else {
            System.out.println("Invalid withdrawal amount.");
        }
    }
}

```
  
## Main Class
```java

public class Main {
    public static void main(String[] args) {

        BankAccount account = new BankAccount("John", 1000);

        account.deposit(500);
        account.withdraw(200);

        System.out.println("Account Holder: " + account.getAccountHolder());
        System.out.println("Balance: " + account.getBalance());
    }
}

```

# What is Happening Here?

- `balance` is **private**
- No direct access like:
    account.balance = 1000000;  //Not allowed
- Only controlled access via methods:

    - `deposit()`        
    - `withdraw()`

    - `getBalance()        

This ensures:

- No negative balance
- No illegal transactions
- Secure system

#### Abstraction

## What is Abstraction?

> **Abstraction is the process of hiding implementation details and showing only essential features to the user.**

In simple words:

- Show **what an object does**
- Hide **how it does it**

Abstraction focuses on **behavior**, not internal working.


#  Why is Abstraction Used?

Abstraction is used to:

1. Hide complex implementation
2. Reduce code complexity  
3. Improve security
4. Improve maintainability
5. Provide a clear structure


# Where is Abstraction Used?
Abstraction is used in:
- Banking systems
- ATM machines
- Online payment systems
- Mobile apps
- Java frameworks (Spring, Hibernate)
- Java libraries

Almost every large application uses abstraction.

# How Abstraction is Achieved in Java?
In Java, abstraction is achieved using
1. **Abstract Classes**
2. **Interfaces**
# 1️ Abstraction Using Abstract Class

## Rules of Abstract Class:

- Declared using `abstract` keyword
- Can contain abstract methods (without body)
- Can contain normal methods
- Cannot create object directly

Example Using Abstract Class

```java

abstract class Animal {

    // Abstract method (no body)
    abstract void sound();

    // Normal method
    void sleep() {
        System.out.println("Animal is sleeping");
    }
}

class Dog extends Animal {

    // Providing implementation
    void sound() {
        System.out.println("Dog barks");
    }
}

public class Main {
    public static void main(String[] args) {

        Animal obj = new Dog();
        obj.sound();
        obj.sleep();
    }
}

```

### Explanation:

- `Animal` defines WHAT animals do (make sound)
- `Dog` defines HOW it does it (barks)

This is abstraction.

#  2️ Abstraction Using Interface

## Rules of Interface:
- All methods are abstract (until Java 7)
- Methods are public by default
- Supports multiple inheritance
- Implemented using `implements` keyword

Example Using Interface


```java

interface Payment {
    void pay(double amount);
}

class CreditCard implements Payment {

    public void pay(double amount) {
        System.out.println("Paid using Credit Card: " + amount);
    }
}

class UPI implements Payment {

    public void pay(double amount) {
        System.out.println("Paid using UPI: " + amount);
    }
}

public class Main {
    public static void main(String[] args) {

        Payment p1 = new CreditCard();
        p1.pay(5000);

        Payment p2 = new UPI();
        p2.pay(2000);
    }
}

```
### Explanation:
- Interface defines WHAT to do → `pay()`
- Classes define HOW to do it

# Difference Between Encapsulation and Abstraction

| Feature     | Encapsulation                       | Abstraction                |
| ----------- | ----------------------------------- | -------------------------- |
| Focus       | Data hiding                         | Hiding implementation      |
| Achieved By | Private variables + getters/setters | Abstract class & Interface |
| Example     | Bank account balance                | Payment system             |
| Level       | Class level                         | Design level               |
