A **closure** is created when a function remembers and accesses variables from its **outer (parent) function**, even after that parent function has finished executing.

- **A closure is a function + the lexical environment in which it was created**
- Lexical environment means: 
		The function remembers variables that were in scope when it was defined.

```javascript
function outer() {
    let outerVar = "I'm in the outer scope!";
    function inner() {
        console.log(outerVar); 
        outerVar = "Updated"
    }
    return inner;  
}
const closure = outer(); 
closure();
closure();


//output
I'm in the outer scope!
Updated
``` 


### Basic Example of Closure

```javascript
function greet() {
  let name = "Vishal";  // variable inside parent function

  function sayHello() { // inner function
    console.log("Hello " + name); // accessing parent's variable
  }

  return sayHello;
}

const fn = greet();  // greet() runs and returns sayHello
fn();  // Output: Hello Vishal

```

- `greet()` has finished executing  
-  But `sayHello()` still remembers `name` → **This is closure**

####  **Why Does Closure Work?**

Because JavaScript stores:
- The inner function code
- **AND** the variables it needs from the outer function
This combination is the closure.


####  **How to Invoke a Function Inside a Closure**

- Call the outer function → it returns another function
- Call the returned function
```javascript
function outer() {
  return function inner() {
    console.log("Inner called");
  };
}

outer()(); // Direct invocation
```


```javascript

function createCounter() {
  let count = 0;

  return function () {
    count++;
    console.log(count);
  };
}

const counter = createCounter();

counter();  // 1
counter();  // 2
counter();  // 3


```

The inner function keeps access to `count`  
Even though `createCounter()` has already finished
This is a real-life use of closures.


### Corner Cases 

#### 1) Closures inside loops (var vs let)

Problem with `var`
```javascript

for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log(i), 1000);
}

//output
3
3
3

```

Why?
- `var` is function-scoped
- All closures refer to the same `i`, which becomes 3 after the loop ends.

Using `let` (Block Scope)
```javascript

for (let i = 1; i <= 3; i++) {
  setTimeout(() => console.log(i), 1000);
}


//output
1
2
3

```


#### 2) Returning objects instead of functions

Closures still work.
```javascript

function person() {
  let age = 20;

  return {
    getAge() {
      return age;
    },
    grow() {
      age++;
    }
  };
}

const p = person();
console.log(p.getAge());  // 20
p.grow();
console.log(p.getAge());  // 21


```


#### 3) Closures keeping reference, not value

Closures remember **reference to variable**, not a copy.
```javascript

function test() {
  let num = 10;

  return () => console.log(num);
}

const fn2 = test();
num = 20;  // Not affecting closure, different scope
fn2(); // Output: 10


```



### Uses of Closures in JavaScript

#### 1) Data Privacy (Encapsulation)
JavaScript has no real private variables (before ES6).  
Closures allow private data.
```javascript

function secret() {
  let password = "abcd123";

  return {
    getPassword: () => password
  };
}


```

#### 2) Implementing Modules
```javascript

const module = (function () {
  let count = 0;

  return {
    increment() {
      count++;
    },
    getCount() {
      return count;
    }
  };
})();


```


#### 3) Function Factories
Closures allow functions to remember preset values.

```javascript

function multiply(x) {
  return function(y) {
    return x * y;
  };
}

const double = multiply(2);
console.log(double(10)); // 20


```

#### 4) Event Handlers

```javascript

function setup() {
  let clicks = 0;

  document.getElementById("btn").addEventListener("click", function() {
    clicks++;
    console.log(clicks);
  });
}


```


#### 5) Debouncing / Throttling
Closures remember timers

#### 6) Asynchronous Programming
Closures preserve variables for callbacks.
