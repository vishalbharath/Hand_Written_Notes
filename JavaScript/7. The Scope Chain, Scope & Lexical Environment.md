
- **Scope** — the region of code where a binding (variable/function) is accessible. In JS: **global scope**, **function scope**, and **block scope** (blocks introduced by `let`/`const`).
- **Lexical scope** — JS’s scoping rule: _where_ a function is written determines what variables it can access, not where it’s called. JavaScript is _lexically scoped_.
- **Lexical Environment** — the internal runtime structure the engine uses to keep track of identifiers (bindings). Think: an object that stores variable names → values and a pointer to its outer (parent) lexical environment.
- **Scope chain** — the chain of Lexical Environments the engine traverses when resolving a variable name: current → outer → outer → ... → global.


#### Lexical Environment

- Whenever an Execution Context is created an **Lexical Environment** is also Created.

>  **Lexical Environment** is the Local Memory along with the Lexical Environment of its Parent

- Lexical means *Hierarchy or in a Sequence* 

```javascript

function a(){
	var b = 10;
	c();
	function c(){
		
	}
}
a()
console.log(b);

```

- In the above code we can say that **C function is Lexically Sitting inside A function**
- Whenever the Execution context is created we also get reference to the lexical environment of its parent
```javascript


const x = 1;             // global env: { x: 1 }

function a() {
  const y = 2;           // a's env: { y: 2 }  -> outer -> global
  function b() {
    const z = 3;         // b's env: { z: 3 }  -> outer -> a's env -> global
    console.log(x, y, z);
  }
  b();
}
a(); // logs: 1 2 3

```

**Why:**  
When `b` runs, its LexicalEnvironment contains `z`. The lookup for `x` goes: `b` → `a` → global and finds `x = 1`. Same for `y`. That chain of references is the **scope chain**.


### Scope chain in Javascript

- The **Scope Chain** in JavaScript is the mechanism the JS engine uses to **find variables**.  
- Whenever you try to access a variable, JavaScript starts searching for it in the **current scope**, and if it doesn’t find it there, it moves **upward through the chain of outer scopes** — until it reaches the **global scope**.
- If the variable is still not found → you get a **ReferenceError**.


Think of the **scope chain** like a chain of boxes inside each other:

- Each function/block is a box.
- Inside a box are variables it defines.
- If a box needs a variable it doesn’t have, it looks into the **next outer box**.
- This continues until it reaches the **global box**.


#### How JavaScript Creates the Scope Chain

Each time code runs in a new scope (global, function, or block):
- The engine creates a **Lexical Environment** with its variables.
- Each Lexical Environment has a reference (called `outer`) to its **parent environment** — the one in which it was defined.
- These references form the **scope chain**.

**Important:**  
The chain is created based on **where functions are written (lexically)**, not where they are called.

```javascript

var a = 10;         // Global scope

function outer() {
  var b = 20;       // Outer function scope

  function inner() {
    var c = 30;     // Inner function scope
    console.log(a, b, c);
  }

  inner();
}

outer();


```

### Step-by-Step:

1. **Global Scope**: contains `a` and `outer`
2. **outer() Scope**: contains `b` and `inner`
3. **inner() Scope**: contains `c`

When `console.log(a, b, c)` runs:
- JS looks for `a` → not in `inner`, goes to `outer`, not there → goes to `global` → finds `10`.
- Looks for `b` → not in `inner`, found in `outer` (`20`).
- Looks for `c` → found in `inner` (`30`).
Output: `10 20 30`

##### The Chain (Visually)

```javascript

inner() Lexical Env
   ↓
outer() Lexical Env
   ↓
global Lexical Env

//Each arrow points to the **outer environment reference**.
```


#### Example: Variable Shadowing in the Scope Chain

```javascript

var x = "global";

function test() {
  var x = "local";
  console.log(x);
}

test();        // "local"
console.log(x); // "global"


```

##### Explanation:
- Inside `test()`, JS finds a **local x** first → it doesn’t go up the chain.
- In the global context, JS uses the **global x**.
- This is called **variable shadowing** — the inner variable hides the outer one with the same name.


### Example: Function Inside Function

```javascript

let p = 100;

function first() {
  let q = 200;
  
  function second() {
    let r = 300;
    console.log(p + q + r);
  }

  second();
}

first();


```

**Scope chain lookup for each variable:**
- `r` → found inside `second`
- `q` → not in `second`, found in `first`
- `p` → not in `second` or `first`, found in global

Output: `600`


#### What If Variable Not Found?

```javascript

function demo() {
  console.log(x); // ❌ ReferenceError
}

demo();


```


There’s **no variable `x`** in any scope (demo → global) → JS throws a **ReferenceError**.



#### Call Site Doesn’t Matter (Lexical Scoping)

```javascript

var name = "global";

function outer() {
  var name = "outer";
  inner();
}

function inner() {
  console.log(name);
}

outer(); // Output: "global"


```

Even though `inner()` is **called inside** `outer()`, it **was defined in the global scope** —  
so its scope chain points to **global**, not to `outer()`.
This proves:
> JavaScript uses **lexical scoping**, not dynamic scoping.
