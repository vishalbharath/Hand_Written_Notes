
- **`undefined`** = _a value_ — the variable **exists** but currently holds no value.
- **“Not defined”** (`ReferenceError: x is not defined`) = the variable **does not exist** (was never declared in that scope).


### UNDEFINED

`undefined` is a primitive value in JS. You see it when:
- A variable is declared but not assigned.
- A function parameter was not passed.
- A function has no `return` (returns `undefined`).
- You access a missing object property or array hole.
- You explicitly set a variable to `undefined`.

```JAVASCRIPT

var a;
console.log(a);           // undefined   (declared, not assigned)

function f(x) { console.log(x); }
f();                      // undefined   (no argument passed)

function g() {}
console.log(g());         // undefined   (no return value)

const obj = {};
console.log(obj.foo);     // undefined   (property doesn't exist)

const arr = [1, , 3];
console.log(arr[1]);      // undefined   (array hole)


```


### NOT DEFINED

- Trying to **read** a variable that was never declared throws a `ReferenceError` — commonly shown as “x is not defined”:
```javascript


console.log(b); // ReferenceError: b is not defined


```



### LOOSELY TYPED LANGUAGE


**Loosely typed** (or **dynamically typed**) means:

> JavaScript variables **do not have fixed types** — only their _values_ do.

You can store any type of data in a variable, and even **change the type at runtime**.

Unlike strongly typed languages (like Java, C++, or TypeScript), where you must declare a variable’s data type before using it, JavaScript determines the type **dynamically** during execution.


#### Example 1 — Same Variable, Different Types
```JAVASCRIPT

let data = 10;       // number
console.log(typeof data); // "number"

data = "Hello";      // now it's a string
console.log(typeof data); // "string"

data = true;         // now it's a boolean
console.log(typeof data); // "boolean"


```

Here, `data` was:
- A number first,
- Then a string,
- Then a boolean — all valid!

That’s what makes JavaScript **loosely typed** — type binding happens **at runtime**, not at declaration.


####  Example 2 — Implicit Type Conversion (Type Coercion)

Because JS is loosely typed, it will **automatically convert** types when needed — sometimes in ways that surprise developers.

```JAVASCRIPT

console.log(5 + "5");     // "55"  → number + string = string
console.log("5" - 2);     // 3     → string "5" converted to number
console.log("5" * "2");   // 10    → both strings converted to numbers
console.log("5" + true);  // "5true" → boolean true converted to string
console.log(5 + true);    // 6     → true converted to number 1


```

This process is called **type coercion**, and it’s a direct result of JavaScript being **loosely typed**.


####  Example 3 — Function Arguments Don’t Enforce Types

- In JS, functions don’t require or enforce specific argument types.
```JAVASCRIPT

function add(a, b) {
  return a + b;
}

console.log(add(5, 10));      // 15   (number + number)
console.log(add("5", 10));    // "510" (string + number)
console.log(add(true, false)); // 1   (true=1, false=0)


```

The same function behaves differently based on **types of inputs**, because JS dynamically decides what to do at runtime.



####  Example 4 — Automatic Type Conversion in Conditions

JavaScript automatically converts values to **boolean** when used in conditionals:

```JAVASCRIPT

if ("hello") {
  console.log("Truthy value"); // runs
}
if (0) {
  console.log("Falsy value"); // doesn’t run
}


```

JS treats:
- `0`, `""`, `null`, `undefined`, `NaN`, and `false` → **falsy**
- Everything else → **truthy**

#### Example 5 — Type Confusion (Pitfalls)

Sometimes this flexibility causes confusing bugs:

```JAVASCRIPT

console.log("10" - "5"); // 5
console.log("10" + "5"); // "105"
console.log(10 + true);  // 11
console.log(10 + false); // 10
console.log(10 + null);  // 10 (null -> 0)
console.log(10 + undefined); // NaN (undefined -> NaN)

```

Because JS decides how to convert types _contextually_, arithmetic (`+`, `-`, etc.) may behave inconsistently.





```JAVASCRIPT

let x = 10;     // number
x = "ten";      // now string
x = true;       // now boolean

function combine(a, b) {
  return a + b; // may perform numeric addition or string concatenation
}

console.log(combine(5, 5));     // 10
console.log(combine("5", 5));   // "55"


```

JavaScript allows this because it’s **loosely typed and dynamically interpreted** — the type is associated with _the value_, not _the variable_.
