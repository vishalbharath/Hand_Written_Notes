```javascript
var x = 1;
a(); //10
b(); //100
console.log(x); //1

function a(){
	var x = 10;
	console.log(x);
}

function b(){
	var x = 100;
	console.log(x);
}
```


## Step 1: Global Execution Context (GEC)

When JavaScript code runs, the **Global Execution Context** is created.  
It has **two phases**:

### 1. **Creation Phase (Memory Allocation / Hoisting phase)**

- All `variables` declared with `var` are hoisted and initialized with `undefined`.

- All `functions` (declared with the `function` keyword) are hoisted _with their entire body_.    

So before execution, JavaScript internally sets up:

`Memory:  x  → undefined a  → function a() {...} b  → function b() {...}`

### 2. **Execution Phase**

Now the code runs line by line:

1. `var x = 1;`  
    Updates `x` from `undefined` → `1`.
    `Memory: x = 1 a = function a() {...} b = function b() {...}`

## 🔹 Step 2: Function `a()` Call

When `a();` is executed:
- A new **Execution Context** is created for function `a`.
- Inside `a()`, memory is set up:
    - `x` → `undefined` (because of `var x` inside `a`).

Then execution happens:

`var x = 10;   // updates local x → 10 console.log(x);  // prints 10`

⚡ Important: This `x` is **local** to function `a`, so it does **not** affect the global `x`.

After finishing, function `a()`’s execution context is destroyed.

## 🔹 Step 3: Function `b()` Call

Now `b();` is executed:

- A new execution context is created for function `b`.
- Memory setup:
    - `x` → `undefined` (local to `b`).

Execution:

`var x = 100;   // updates local x → 100 console.log(x); // prints 100`

Again, this is **local** `x`, not the global one.

After finishing, function `b()`’s execution context is destroyed.


## 🔹 Step 4: Global `console.log(x)`

Back in the global context:

`console.log(x); // global x`

The global `x` is still `1` (unchanged by functions).  
So it prints: **1**

## 🔹 Final Output

`10 
`100
`1`
