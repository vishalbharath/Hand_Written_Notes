 -  Let us take an code to understand it Easily
```javascript
var n = 2
function square (num){
	var ans = num * num
	return ans
}
var square2 = square(n);
var square4 = square(4);
```

- *Execution context* is Created when an code is Executed
- *Execution context* is created in Two phases
	- 1st Phase is *Creation phase* Also known as *Memory Creation Phase*
	- 2nd phase is *Code execution phase*

#### Memory Creation Phase

- In the First step Js will *allocate memory to all the variables and functions*
- When allocating memory for n (in the above example) it stores a *special value* known as *Undefined*
- When allocating memory for the function square it stores the entire code inside the function 
- When allocation memory for the variable square2 and square4 it stores *Undefined*

#### Code Execution Phase

- In this phase JS once again runs through the whole JS program line by line and executes the code
- Here in the first step now the value of n is changed from undefined to 2
- In the next step it goes to the function as there is nothing to be executed in the function it then goes to the line 6
- In the line 6, *Function invocation* takes place 
- Functions are the *Heart of Javascript*
- When a function is invoked a *New Execution context is created*
- When a function is invoked a new *Execution context is created* inside the *Global Execution Context*
- Inside the New *Execution Context* again the same process happens that is Memory allocation and code execution 
- After the execution of the new Execution Context it Comes out and executes the Global Execution context and Completes

### Call Stack in JavaScript

- It is very Difficult for the JS Engine to manage these process
- It Handles Everything to manage this execution Context creation , Deletion and the control. It manages a stack 
- This Stack is known as *Call Stack*
- The **call stack** is a **stack data structure** used by JavaScript’s engine to keep track of function calls.
- It follows **LIFO (Last In, First Out)** principle.  The last function pushed (called) will be the first one popped (finished).
- First the *Global Execution Context* is pushed inside the Stack
- When a function is **invoked** or a new **Execution context** is Created , it gets **pushed** onto the stack.
- If that function calls another function, the new function is also **pushed** on top.
- When a function completes, it gets **popped** off the stack.
- JavaScript continues execution from the function below it in the stack.

- ****CALL STACK MAINTAINS THE ORDER OF EXECUTION OF THE EXECUTION CONTEXT***
- Call stack is also Called as *Execution context stack, Program stack, Control Stack, Runtime Stack, Machine Stack*
- Example Of a call stack

```javascript
function first() {
  console.log("First function");
  second();
}

function second() {
  console.log("Second function");
  third();
}

function third() {
  console.log("Third function");
}

first();

//output
Call Stack:
------------
third()
second()
first()

```
